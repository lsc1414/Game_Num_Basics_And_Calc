---
description: 生成游戏机制深度研究文档（理论/实践/案例）
---

1.  **确认研究主题**

    - 明确用户需要研究的游戏机制或系统（例如：仇恨系统、掉落机制、寻路算法）。
    - 确定文档保存路径（通常在 `Design/` 或 `Tech/` 目录下）。

2.  **生成文档结构**

    - 创建一个新的 Markdown 文件，包含以下标准章节：

    ```markdown
    # 🧙‍♂️ [主题名称] 深度研究

    ## 📚 1. 理论基础 (Theoretical Basis)

    - **核心定义**: 该机制的学术或通用定义。
    - **数学模型**: 相关的公式、曲线或算法（如适用）。
    - **设计心理学**: 该机制如何影响玩家体验（心流、奖励反馈等）。

    ## 🛠️ 2. 实践应用 (Practical Implementation)

    - **Vampirefall 适配**: 结合本项目（塔防+肉鸽+Looter）的特性进行设计。
    - **数据结构**: 建议的 C# 类结构或 JSON 配置格式。
    - **伪代码/逻辑**: 关键算法的实现思路。
    - **Unity 实现**: 具体的组件设计或性能注意事项。

    ## 🌟 3. 业界优秀案例 (Industry Best Practices)

    - **案例分析**: 选取 2-3 个知名游戏（如《Hades》、《Slay the Spire》、《Kingdom Rush》等）的同类机制。
    - **优缺点对比**: 分析它们为什么好，以及潜在的缺陷。
    - **借鉴点**: 我们应该模仿什么，规避什么。

    ## 🔗 4. 参考资料 (References)

    - 📄 相关论文 (Papers)
    - 📺 GDC 演讲 / 视频分析
    - 🌐 技术博客 / Wiki 链接
    ```

3.  **撰写内容要求**

    - **语言**: 必须使用 **中文**。
    - **图标**: 标题和关键点必须使用 Emoji 图标以增强可读性。
    - **详细举例**: 每个部分都必须包含具体的例子，不能只有空泛的理论。

4.  **MkDocs 兼容性规则** ⚠️

    以下规则至关重要，违反将导致公式/表格渲染失败：

    ### 4.1 数学公式规则

    | ❌ 错误写法                   | ✅ 正确写法                   | 说明                                   |
    | ----------------------------- | ----------------------------- | -------------------------------------- |
    | `- **公式:**`<br>`  $$F=ma$$` | `**公式:**`<br><br>`$$F=ma$$` | 公式块**不能**紧跟列表项，必须独立成段 |
    | `$$A=B$$`<br>`$$C=D$$`        | `$$A=B$$`<br><br>`$$C=D$$`    | 连续公式块之间**必须有空行**           |
    | `  $$F=ma$$`                  | `  $$F=ma$$` (列表内)         | 列表内的公式块**必须保持缩进**         |
    | `$ expr $`                    | `$expr$`                      | 内联公式**紧贴** `$` 符号，无空格      |
    | `UV\_{new}`                   | `UV_{new}`                    | 下标**不需要**转义                     |
    | `A*{up}`                      | `A_{up}`                      | 下标用 `_` 不是 `*`                    |

    ### 4.2 表格规则

    | ❌ 错误写法     | ✅ 正确写法 |
    | --------------- | ----------- | --- | --- | ------------------- | --- | --- | --- |
    | `文本内容`<br>` | A           | B   | `   | `文本内容`<br><br>` | A   | B   | `   |

    > 表格前**必须有空行**，否则会与上方内容连在一起。

    ### 4.3 函数名包装

    在 `$$` 公式块中，HLSL/数学函数需要用 `\text{}` 包装：

    ```latex
    ✅ $$F = \text{lerp}(A, B, t)$$
    ❌ $$F = lerp(A, B, t)$$
    ```

    常见需要包装的函数：`saturate`, `lerp`, `step`, `smoothstep`, `frac`, `floor`, `ceil`, `tex2D`, `dot`, `cross`, `normalize`, `clamp`, `abs`, `pow`, `atan2`

5.  **自我审查**

    - 检查是否涵盖了理论、实践和案例三个维度。
    - 检查是否包含具体的参考链接。
    - **运行自动修复**: `python scripts/mkdocs_lint_fix.py <新文件路径>` (该脚本会自动修正缩进和公式格式)

6.  **更新索引 (Update Indexes)**

    - **更新 `mkdocs.yml`**:

      - 打开 `mkdocs.yml` 文件。
      - 找到 `nav` 配置块。
      - 将新文档的路径添加到合适的分类下。
      - 格式：`- Emoji 标题: 路径/文件名.md`
      - 示例：
        ```yaml
        - 🏗️ 架构与系统:
            - 新系统名称: Tech/Architecture/New_System_Name.md
        ```

    - **更新 `docs/Full_Index.md`**:

      - 打开 `docs/Full_Index.md` 文件。
      - 找到对应分类的章节。
      - 添加新文档的链接。
      - 格式：`- [文档标题](相对路径/文件名.md)`
      - 示例：

        ```markdown
        ### Tech/Architecture

        - [新系统名称](Tech/Architecture/New_System_Name.md)
        ```
